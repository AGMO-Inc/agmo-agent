# Issue Start Workflow

이 스킬로 이슈 기반 작업 시작을 표준화한다.

## 0. 레포 식별

`git remote -v`로 현재 레포의 `<owner>/<repo>`를 추출한다. 이후 모든 gh 명령에서 사용한다.

```bash
REPO=$(git remote get-url origin | sed -E 's#.+[:/]([^/]+/[^/.]+)(\.git)?$#\1#')
```

## 1. 이슈 조회
1. 사용자에게 이슈 번호를 확인한다.
2. gh 명령어로 현재 레포의 이슈를 조회한다. (gh가 없다면 사용자에게 다운로드 및 인증을 요청한다.)
3. 제목, 본문, 라벨(유형), 체크리스트 항목을 추출한다.
```bash
gh issue view <이슈번호> --repo "$REPO" --json title,body,labels
```

## 2. TODO-Issue.md 갱신
1. `TODO-Issue.md`를 현재 이슈 기준으로 덮어써 최신화한다. 해당 파일이 없다면 새로 생성한다.
2. 이슈 본문을 읽고 코드베이스를 탐색하여 **구체적인 실행 계획**을 수립한다.
3. 다음 템플릿을 따른다.

### TODO-Issue.md 템플릿

```markdown
# TODO-Issue

- 레포: <owner>/<repo>
- 이슈: #<이슈번호>
- 제목: <이슈 제목>
- 링크: <이슈 URL>

## 이슈 요약

(이슈 본문에서 배경/요구사항을 간결하게 발취)

## 실행 계획

(코드베이스를 탐색하여 구체적인 수정 대상과 방법을 기록한다)

### 1. 수정 대상 파일

| 파일 | 변경 내용 | 비고 |
|------|-----------|------|
| `path/to/file.kt` | 필드 추가/수정 내역 | 이슈 범위 내 |
| `path/to/test.kt` | 테스트 추가 | 이슈 범위 내 |

### 2. 범위 외 항목 (선택)

| 파일 | 내용 | 비고 |
|------|------|------|
| `path/to/other.kt` | 관련되지만 이슈 범위 외 | 사용자 확인 필요 |

## 실행 과제

- [ ] 과제 1 (실행 계획에서 파생)
- [ ] 과제 2
- [ ] 테스트 작성/실행

## 참고

- 이슈 본문의 레퍼런스, 제약사항, 주의사항
```

### 작성 규칙

1. **이슈 요약**: 이슈 본문의 배경/요구사항을 2~3줄로 압축한다. 본문 전체를 복사하지 않는다.
2. **실행 계획**: 이슈를 읽은 후 코드베이스를 탐색(`grep`, `find`, AST 검색 등)하여 구체적인 수정 대상 파일과 변경 방법을 기록한다.
   - 수정 대상 파일을 표로 정리한다.
   - 이슈 범위 내/외를 판단하여 구분한다.
   - 범위 외 항목은 사용자 확인을 위해 별도 기록한다.
3. **실행 과제**: 실행 계획에서 파생된 구체적 체크리스트를 작성한다. 이슈 본문의 체크리스트를 그대로 복사하지 않고, 코드 분석 결과를 반영한다.
4. **참고**: 이슈 본문의 레퍼런스 링크, 제약사항, 주의사항을 기록한다.

## 3. 브랜치 생성

1. `develop` 브랜치에서 분기한다.
2. 이슈 유형을 라벨/제목에서 판별한다.
3. 규칙에 맞는 브랜치를 생성한다.
   - Bug: `fix/영향도메인-#이슈번호`
   - Feature: `feature/영향도메인-#이슈번호`
   - Task: `feature/영향도메인-#이슈번호`
4. 영향 도메인이 불명확하면 사용자에게 짧게 확인 후 생성한다.

```bash
git checkout develop
git pull origin develop
git checkout -b <브랜치명>
```

## 4. 프로젝트 보드 상태 변경

1. `AGENTS.md`에서 프로젝트 URL을 확인한다.
2. 프로젝트가 연결되어 있으면 이슈를 `In Progress`로 이동한다.

```bash
project_url="$(grep -E '^- 프로젝트 url:' AGENTS.md | sed 's/^- 프로젝트 url:[[:space:]]*//')"
project_number="$(echo "$project_url" | grep -oE '/projects/[0-9]+' | cut -d/ -f3 || true)"
```

프로젝트 번호가 있으면 `git-issue-move` 스킬의 절차에 따라 `In Progress`로 상태를 변경한다.

## 5. 결과 보고
1. 갱신된 `TODO-Issue.md` 핵심 항목을 요약한다.
2. 생성된 브랜치명을 공유한다.
3. 다음 단계(구현 시작 또는 커밋 준비)를 제안한다.
## 6. 안전 규칙

1. 이 스킬은 `TODO-Issue.md` 작성과 브랜치 생성만 수행한다. 코드 수정은 하지 않는다.
2. `develop` 또는 `main` 브랜치에서 직접 작업하지 않는다. 반드시 브랜치를 생성한 후 작업한다.
3. 이슈가 존재하지 않으면 오류를 보고한다.
4. 브랜치명이 이미 존재하면 사용자에게 확인한다.
